# v0.2.0 평가 — 사전 릴리스

2026-09-07, Galaxy S24 Ultra SM-S928N / Android 16(API 36). 같은 배포 서명키로 v0.1.0에서 데이터 유지 업데이트를 검사했다. 실제 사용자 PDF는 제공되지 않았다. 모든 공개 자료·측정 문장은 고정 합성 자료이며 실제 마이크 음성·회의 로그·인증키는 배포하지 않는다.

## 기능 검사

- 웹 36개 단위 사례: 공통 산술 11개, 공통 판정 6개, 누적/해제, 일반 지식의 중립성, 시점 민감 주장 보류, 근거 충돌·검색 실패, v1 읽기·v2 보존, 입력 제한, 5초 전환·취소·늦은 결과 무시, 401/402/429/네트워크 실패 후 단일 로컬 전환.
- Android 단위 검사 9개: 같은 산술·판정·정책 JSON, 수정/불확실 화자/중복 집계, v1 읽기, 모델 지식 중립, 지연 취소 및 오류 경로.
- S24 합성 음성 저장: 61초 PCM + 일시정지 + 1초 PCM → 60초/1초/1초 WAV, 정확한 RIFF 크기와 16kHz·16비트·모노 형식, 정지 중 입력 제외, 여러 파일을 가로지르는 발언 참조, 실제 MediaPlayer 재생 통과.
- S24 ENOSPC 쓰기 오류 주입: 저장 실패 알림 및 추가 입력 거부 통과. 실제 저장 공간을 소진하지 않았다.
- S24 실제 마이크: 약 1.8초 듣기 → 1.2초 정지 → 약 1.8초 재개 → 앱 배경 이동. 동일 회의 유지, 두 녹음 파일과 정지 구간 부재, 자동 일시정지·종료 기록 유지 통과. 이 음성은 폰에만 보관했다.
- 미완성 WAV 헤더·JSONL 마지막 부분·회의 JSON 손상을 복구했다. 별도 합성 녹음 중 `am force-stop`으로 앱 프로세스를 종료한 뒤 앱을 다시 실행해 WAV·JSONL·메타데이터의 복구와 다운로드 컬렉션 공개 상태를 확인했다.
- 실제 웹 WASM 음성 모델을 로컬 캐시에 적재하고 외부 네트워크를 차단한 상태에서 마이크 중지·재개를 검사했다. 모든 이전 마이크 track이 종료되고, 같은 화자 worker가 유지되며, 이전 세대의 지연된 발언은 반영되지 않았다. 입력 음성은 브라우저의 합성 장치였다.
- PC Chromium 웹 화면: 산술 정답/오답, PDF 처리, 412px 화면 가로 넘침 없음, 페이지 JavaScript 오류 없음. PDF.js의 구형 Chromium `Uint8Array.toHex` 오류는 같은 고정 패키지의 호환 빌드로 해결했다.

## 시간 측정

아래 수치는 소수 회의 기능 검사이며 p95나 대표 한국어 회의 정확도 지표가 아니다. 모델 다운로드/준비 시간은 추론 시간과 분리했다. `토큰 상한`은 시스템 프롬프트·JSON·대화 형식을 포함한 UTF-8 바이트 수를 이용한 보수적 상한이며 실제 tokenizer 개수는 아니다.

| S24 항목 | 측정 |
| --- | --- |
| `1+1은 2입니다` | 0–15ms, `VERIFIED`, 계산기만 사용 |
| 지구 공전 일반 지식 / 로컬 1.7B | 약 7.9초, `UNVERIFIABLE` — 일반 지식 상태로 답하지 못함 |
| 24V 고정 매뉴얼 / 로컬 1.7B | 약 14.1초, `VERIFIED` |
| 강제로 느린 공급자 전환 | 5,000ms, 로컬 취소, 클라우드 대역 1회 |
| 실제 llama.cpp 생성 중 취소 | 약 5,000ms, 취소 후 클라우드 대역 1회 |

클라우드 대역은 테스트 함수다. OpenRouter 실서버 응답속도·요금·실제 계정 인증 성공을 측정한 것이 아니다. 선택한 모델이 연결되면 자동 모드는 기존 S24의 7.5초 이상 지연/웹 GPU 실패 관측을 초기 예상에 반영해 처음부터 해당 모델로 보낸다. 모델 준비 부족·긴 입력·대기열·최근 지연이 예측에 반영된다. 연결 또는 모델 선택이 없으면 로컬을 유지하며 설정을 안내한다.

### 같은 1.5MB, 다른 텍스트 밀도

`scripts/pdf-fixtures.py`로 생성했다. PDF 주석 패딩으로 파일 크기를 각각 정확히 1,500,000바이트로 맞추었으므로 일반적인 1.5MB 사용자 PDF 전체를 대표하지 않는다.

| 환경 | 3페이지 / 발췌 24개 | 150페이지 / 발췌 13,500개 |
| --- | --- | --- |
| S24 추출+색인 | 228–263ms | 3,689–4,767ms |
| S24 발언별 발췌 검색 | 2–3ms | 130–160ms |
| PC Chromium 추출+색인 | 약 637ms | 약 773ms |
| PC Chromium 발췌 검색 | 약 0.6ms | 약 11.6ms |

PDF 처리 측정은 초기 v0.2 프롬프트에서 입력 상한 2,734(S24)/2,691(웹)토큰이었다. 일반 지식 지시를 보강한 최종 S24 프롬프트는 2,502토큰 상한으로, 같은 2,800 한도에 맞춰 낮은 관련도의 문단을 제외했다. PDF를 다시 읽지 않고 색인된 문단을 검색한다. UI에는 처음 50개 발췌를 미리 보여주고 전체 자료는 색인·저장한다.

- light SHA-256: `42c1d92977a3a4110fba503b4893a9a8db71e1233d55b90978764a06b06e56e5`
- dense SHA-256: `1bf53ccba3da3db47c0b08b9674442bae09124acb465e679f6efbd724e089064`

## 남은 한계

실시간 완료 기준은 통과하지 못했다. 로컬 모델이 일반 상식을 보류한 사례를 소스 검증 성공으로 바꾸거나 근거 없는 단정으로 집계하지 않는다. `GENERAL_KNOWLEDGE` 상태와 정책은 공통 사례로 검사했지만 모델의 실제 분류 품질과는 구분한다.

한국어 2/4/6인 macro-F1·검증 정밀도·화자 정확도·기권 비율, 60분 발열/메모리/배터리/자기 음성 재인식은 대표 자료로 재평가하지 않았다. 실기기 웹 WebGPU 로컬 생성은 v0.1의 실패 관측을 대체할 검증 성공이 없다. 실제 OpenRouter 로그인/잔액/결제·검색 품질, 장시간 저장 실패 복구와 OEM 강제 종료의 모든 변형도 검증하지 않았다. 따라서 APK·웹·Release 모두 사전 릴리스 표시를 유지한다.

의존성 버전은 변경하지 않았다. `npm audit` 취약점 보고 0건. PDF 호환 경로는 기존 고정 PDF.js 패키지에 포함된 빌드다. 기존 개발 컨테이너 이미지의 v0.1 보안 스캔 한계는 그대로이며, 이번 앱 수정으로 해결했다고 주장하지 않는다.

## 재현

```sh
npm test
npm run build
python3 scripts/pdf-fixtures.py /path/to/test-artifacts
cd android
./gradlew testDebugUnitTest assembleDebug assembleDebugAndroidTest assembleRelease
```

S24 instrumentation: `ArchiveIntegration`, `MicrophoneIntegration`, `PdfIntegration`, `V2InferenceIntegration`. PDF fixture는 기기의 앱 전용 `files/meg-v2-light.pdf`, `files/meg-v2-dense.pdf`에 배치한다. `CrashIntegration#createPendingForExternalProcessKill`의 `MEG_CRASH_READY` 후 해당 앱만 force-stop하고 다시 실행한 다음 `verifyRecoveryAfterRelaunch`를 실행한다. 이 검사는 합성 PCM만 만들고 자기 검사 파일만 삭제한다. `MicrophoneIntegration`은 실제 주변 음성을 저장하므로 해당 기록을 공개 산출물에 복사하지 않는다.
